[제품 목표 — 반드시 유지]
사용자는 “나한테 맞는 공고 찾아줘”라고만 해도 시작할 수 있다.
현재 대화와 실제 접근 가능한 관련 AI 메모리를 먼저 이용하고, 판단을 바꾸는 부족한 개인 사실만 질문한다.
설문·JSON·이력서·DB·새 계정·Python 설치를 일반 사용자의 시작 조건으로 강요하지 않는다.
검색어·기업군·산업·도구·조사 순서·분업·탐색 깊이는 AI가 상황에 맞게 선택한다.
고정 기업 수/검색 횟수/상위 추천 수를 채웠다는 이유로 끝내지 않는다.
검색 자율성은 유지하되, 수집 누락·잘못된 제외·보고 요약 중 누락은 별개로 검수한다.

[보고와 후속 지원]
기본 결과는 기준일/한 줄 결론, 마감순 공고, 사용자 근거, 핵심 위험, 클릭 가능한 실제 공고/지원 URL, 다음 행동이다.
반복 보고는 새 공고·중요 변경·마감 임박 중심이다. 변화 없는 장문 설명과 기술 통계는 기본 출력하지 않는다.
추천이 많으면 덜 중요한 곳도 한 줄로 남기고, 실제로 없는 펼침 화면/버튼/목록/새채팅 URL을 만들지 마.
공식 기업 공고, 외부 ATS 지원, 플랫폼 전재, 기업 홈을 구분해. URL의 실제 역할·회차·리다이렉트·로그인 요구를 확인하고 토큰을 노출하지 마.
사용자가 원하는 공고를 골랐을 때만 “현재 채팅에서 지원 준비” 또는 “복사 가능한 새 채팅용 프롬프트”를 제공해.
다른 AI가 이전 대화나 다른 공급자의 메모리를 읽는다고 가정하지 말고, 선택한 직무·최신 URL·마감·검증시점·최소 관련 개인 근거·미확인 사항·현재 단계·다음 작업만 인계해.
문항/글자수/성과/자격/접수완료를 만들어내지 말고, 새로운 제출·기업 연락은 별도 허락을 받아.
사용자가 후속 준비를 원하지 않으면 보고와 링크만 제공하면 된다.

[누락 방지 — 방법 제한 대신 검증 책임]
실제 업무·직무명 변형·여러 산업·기업 직접 목록·다른 검색경로를 상황에 맞춰 활용해.
최근 공고만 보지 말고 오래된 모집 중·상시·재공고·연장·혼합 공채의 개별 직무도 확인해.
중요한 불확실 제외를 재검토하고, 다른 경로에서 적합 공고가 나오면 그 누락 유형의 다른 후보까지 추가 탐색해.
미탐색 영역의 최초 시점과 재점검 이유를 보존해 같은 영역이 무기한 밀리지 않게 해.
발견 후보→판정→실제 보고/실재 접근 가능한 목록을 연결해 요약 중 누락을 잡아.
모든 공고를 다 찾았다는 보장, 기록 없는 전수조사/저장 성공/실행 성공 주장은 금지해.
전체 검색이 부분 완료여도 개별 검증된 추천은 제공하고, 중요한 공백만 짧게 밝혀.

[호환성 검증]
GPT/ChatGPT와 Codex, Claude 채팅/Cowork와 Claude Code, Gemini 앱과 Gemini CLI, API 환경을 구분해.
공식 최신 문서와 실제 설치된 UI/버전/도구를 확인해. 모델명만으로 웹·메모리·저장·예약·파일 권한을 가정하지 마.
공통 SKILL.md를 기준으로 배포물을 생성하고, 특정 공급자의 도구명이나 무조건적인 API 키/DB 의존을 넣지 마.
계정의 네이티브 스킬/플러그인 경로, CLI 폴더, 단일 파일 지침 대체 경로를 구분해 안내해.
폴더 복사/ZIP 업로드/버전 로드/참고자료 접근/실제 도구 실행/저장/예약/알림은 각각 다른 검증 단계다.
스킬 메뉴가 없으면 현재 가능한 한 파일 지침 경로로 시작할 수 있게 하되 네이티브 설치 성공처럼 쓰지 마.
라이브 환경에서 가능한 것부터 실제 시험하고, 불가능한 것은 환경명·차단 원인·not_run을 남겨.
API 키/유료호출/새 계정이 없다고 로컬 작업 전체를 중단하지 말고, 결제·가입·비밀정보 요구는 임의 진행하지 마.

[코드와 평가]
1. python -m unittest discover -s tests -v
2. python scripts/build_release.py
3. 현재 소스와 배포 ZIP의 경로·해시·참고파일·버전 일치 확인
4. 실제 사용할 수 있는 각 호스트에서 스킬을 로드하고 읽힌 버전을 확인
5. 테스트 인물로 메모리 충분/불충분/없음, 웹 있음/없음, 저장 실패, 직접 링크, 공고 선택, 다른 AI 인계까지 시험
6. tests/fixtures/discovery의 합성 출처와 tests/fixture_browser.py로 실제 모델 조사 실행 기록을 만들고 평가
7. tests/oracles의 정답/과거 정답 노출 대화를 분리한 새 세션에서 실행하고, 평가자가 tests/evaluate_capture.py로 별도 채점
8. 기존 방식과 새 스킬을 가능한 동일 자원·입력 조건으로 비교해 발견·누락·잘못된 제외·URL/마감 오류·보고 누락·질문 부담을 확인

82개 로컬 검사는 보조 코드/파일의 검사다. 64개 행동 시나리오 정의는 실제 모델 평가 결과가 아니다.
현재 수치를 개선 후에도 고정하지 말고 실제 실행 결과로 갱신해. 평가하지 않은 사례에 통과를 적지 마.
테스트 통과를 위해 핵심 조건이나 테스트를 무력화하지 말고 재현되는 결함을 고쳐.
호스트 자동화가 없으면 수동 확인이 필요한 정확한 최소 단계를 남겨. 존재하지 않는 검증 결과를 만들지 마.
실환경 미검증이 남으면 개발 프리뷰/RC로 공개 범위를 정직하게 표시해.

[GitHub·권한·개인정보]
현재 환경의 실제 GitHub 쓰기 도구 또는 인증된 git 권한을 먼저 확인해. 앱 연결이 push 권한이라는 가정은 금지해.
선택된 저장소가 있으면 별도 브랜치를 사용하고 기존 작업을 보존해.
선택된 저장소가 없으면 연결된 내 개인 계정에 비공개 job-research-skill 저장소를 만드는 것까지 허용한다.
동명 저장소나 조직 저장소는 임의 덮어쓰기/선택하지 마. 권한이 없으면 검수/빌드 결과와 정확한 차단 사유를 남겨.
ZIP만 올리지 말고 소스·설치 문서·테스트·공식 근거·검증 결과를 읽을 수 있게 커밋해.
공개 전환과 라이선스 선택은 마지막에 한 번에 내 승인을 받아. MIT는 제안일 뿐 아직 적용된 라이선스가 아니다.
실제 사용자 메모리·이력서·메일·지원 결과·토큰·개인 도구 로그는 공개 예제/커밋에 넣지 마.
네트워크 요청, 외부 분석 전송, 자기소개서 자동 제출, 개인정보 수집, 유료 인프라를 불필요하게 추가하지 마.
허가된 커밋/push 후에는 실제 원격 커밋과 파일을 다시 확인해.
이 작업은 기존 개인 채용 리서치 예약이나 알림을 변경할 권한이 아니다.
