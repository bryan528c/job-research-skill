# 최종 검토와 반영 — v0.2.0-rc.2

## 이전 인계 기록 (rc.1)

0.1.1 ZIP의 18개 파일을 확인했고 기존 정적 검사 12개가 통과했다.
기존 검토 문서는 호스트 설치/메모리/저장/실제 채용 검색 품질이 미검증임을 명시했다.
따라서 과거 파일이 GPT·Claude·Gemini 어디서나 이미 검증됐다고 볼 수 없다.

## 이번 변경

1. 공통 Agent Skills 본체와 환경별 설치 경로를 분리했다. 업로드 ZIP 두 형태,
   OpenAI plugin 포장, CLI별 선택 설치, 단일 파일 대체판을 한 소스에서 생성한다.
2. 링크를 출처/공식직무/실제지원/홈페이지/대체경로로 구분한다. 토큰·실행 스킴·
   사설주소를 방어하고 역할·회차 확인을 요구한다. 링크 문법 검사는 실시간 검증이 아니다.
3. 선택한 공고만 같은 채팅에서 계획하거나 새 대화용 최소 프롬프트를 만들도록 했다.
   보고번호를 회차/직무 ID에 연결하며, 다른 AI의 메모리 자동 공유를 가정하지 않는다.
4. 누락을 수집·잘못된 제외·보고 누락으로 나눴다. 완료/반례검색/미탐색 기록 및
   후보-보고 일치 검사 코드를 추가했다. 증거 ID의 존재가 웹 열람의 진위를 증명하지 않는다.
5. 로컬 보조 설치기는 기본 미변경 계획만 출력하고 --apply에서 복사한다. 기존 파일
   덮어쓰기·자동 결제·원격 업로드·예약 변경은 하지 않는다.
6. 정적 검사 외에 실제 보조 코드 단위 테스트, 오프라인 합성 공고 fixture와 결과
   평가기를 추가했다. 모델 평가 시나리오 64건과 실제 모델 평가 결과는 구분한다.

## 남는 한계

어떤 프롬프트도 공개 웹의 모든 공고를 빠짐없이 찾았음을 증명하지 못한다.
검색 색인 지연, 비공개·로그인 공고, 계정 권한, 플랫폼 차단, 변경·조기종료,
모델의 도구 선택/분류 오류, 원문 오독 등이 남는다. 범위와 미확인 상태를 남기고
새 발견으로 드러난 영역을 재탐색하며 실제 host traces와 결과로 평가해야 한다.

이 패키지는 별도의 상용 백엔드가 아니라 호스트의 도구로 실행하는 스킬이다.
정적/보조코드 통과는 호스트가 지침을 지켰다는 보장이 아니다. rc.1 당시 실제 GPT·Claude·Gemini 실행은 미완료였다. rc.2에서는 아래 Work 실행을 추가했으며 다른 실환경 미검증이 남아 RC/개발 프리뷰를 유지한다.

사용자 입출력은 자연어 한 문장과 짧은 링크 보고다. 내부 검사·원장·평가 자료는
일반 사용자에게 작성시키지 않는다. 기존 개인 채용 예약·알림·실제 경력 메모리는 수정하지 않았다.

## rc.2에서 실제 고친 문제

1. 실제 Work 설치 검증기에서 `compatibility` 최상위 메타데이터가 거부됐다. 같은 제약을 본문으로 옮겨 사용자 동작과 호환성 정보를 유지했다. 설치 검증기를 통과한 실제 개인 스킬을 저장하고 새 세션에서 읽었다.
2. 원본 설치기는 스킬 루트 심볼릭 링크와 프로젝트 위 조상 경로 심볼릭 링크를 검사하지 않았다. 이를 거부하도록 고치고 회귀검사를 추가했다.
3. 배포를 재생성해도 원본 PACKAGE_MANIFEST 해시는 갱신되지 않았다. 재빌드에 원본 목록 갱신을 넣고 원본/ZIP/버전/참고파일/단일파일 일치를 별도 검증한다. 출력 폴더의 관계없는 ZIP도 배포물로 채택하지 않는다.
4. 합성 평가기는 관찰하지 않은 공고 판정과 상충하는 판정을 허용했다. 실제 출처 명령 반환을 기록하고, 판정 집합과 열린 공고의 일치를 검증하도록 보강했다. 기록 해시가 호스트 서명이나 웹 조사 완전성 증거는 아니다.
5. 실제 웹 실행에서 기본 보고에 제외 목록이 길게 붙었다. 중요한 제외만 본문에 언급하고 상세 검토는 작업 기록에 남기도록 보고 참고지침을 명확히 했다. 추천 개수·검색 횟수 제한은 추가하지 않았다.

## 평가 결론

고정 합성 자료에서 기본 방식과 스킬 방식 모두 정답 추천 9건을 찾았다. 잘못된 제외와 추천의 보고 누락은 없었다. 검색 성능 개선이 입증된 것은 아니다. 초기 스킬 보고가 더 짧았지만 반복·실시장 검증을 대신하지 않는다.

단일 파일 인계, 합성 메모리 충분/불충분/없음, 웹 없음, 실제 파일 쓰기 실패, 선택 공고의 현재 채팅 준비를 관찰했다. 실제 개인정보와 플랫폼 장기기억은 이 시험에 쓰지 않았다. 호스트별 검증 단계와 GitHub 배포 상태는 compatibility.ko.md 및 github-readiness.ko.md에 분리했다.

보고 참고지침 보완 후의 새 웹 실행에서도 제외 목록과 설명이 길게 남았다. 따라서 간결성은 해결 완료로 표시하지 않고 partial로 기록했다. 반복 실환경 평가에서 보완할 항목이다.
