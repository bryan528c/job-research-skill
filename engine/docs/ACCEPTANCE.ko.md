# 인수 기준 — 단위 테스트 통과와 조사 제품 완성을 분리

## 현재 alpha의 로컬 합격 조건

실제 SQLite에서 다음이 성립해야 한다.
- 회사 모집단을 읽지 않은 broad run은 만들지 않는다.
- 등록한 회사 중 채용 출처가 없으면 조사 작업으로 남는다.
- 다음 페이지를 빠뜨리거나 total이 다르면 해당 source는 완료가 아니다.
- crash/lease expiry 후 재개되고 이전 worker가 stale commit을 못 한다.
- 이전 후보·접수·미지원 이력이 새 조사로 넘어가도 삭제/잘못 일반화되지 않는다.
- job 불발견/403/파서 오류가 모집 종료나 지원 불합격으로 바뀌지 않는다.
- 개인조건·공고 변경시 평가는 stale로 내려가고 재검토가 필요하다.
- 유효 추천이 최종 보고에서 빠지면 저장에 실패한다.
- 보고 번호는 보고ID와 연결되며 다른 사용자의 기록을 선택할 수 없다.
- 외부 텍스트를 명령으로 실행하지 않고 private/credential URL을 허용하지 않는다.

## Codex가 실제로 끝내야 할 조건

### A. 실제 모집단

공식 기업집단/중견/상장/공시 명부의 접근 가능한 경로를 실제 확인하고 확보한다.
각 source의 날짜·범위·전체 행 수·원본 해시·가져온 수·누락/오류·중복 관계를 기록한다.
상장=중견, 그룹 소속=법인 대기업, 전체 공시회사=한국 전체 기업으로 분류하지 않는다.
일부 명부를 확보하지 못하면 전체 분모는 미확정으로 남기고 나머지 실제 작업을 계속한다.
몇 백 개 기업을 임의 선정해 전국 조사라고 마무리하지 않는다.

### B. 국내 실제 수집

국내 주요 그룹 공식 채용, 중견기업의 독립 채용페이지, 채용 플랫폼/공공 API를 상호보완한다.
공식 목록→개별 직무→실제 지원주소까지 실제로 열고 페이지·cursor·필터 끝을 검증한다.
JS/이미지 모집요강과 혼합 공채의 직무별 자격을 처리하고, 막힌 source만 격리한다.
Greenhouse/Ashby 몇 곳의 성공만으로 한국 시장 대응을 완료 처리하지 않는다.

### C. 세션을 넘는 운영

실제 사용자 프로필과 과거 후보를 private store로 이관하되 원본 근거와 신뢰 수준을 보존한다.
별도 새 세션에서 같은 작업을 복구하고 사용자 결정·남은 범위·원래 갭 나이를 대조한다.
서로 다른 worker, 도중 종료, URL 이동/페이지 중복/공고 수정/조기마감의 회귀 검증을 수행한다.
파일을 만들었다는 것과 예약에서 접근된다는 것을 구분한다.

### D. 실제 AI 실행

새 엔진을 사용한 도구 로그를 남긴다. 서로 다른 검색경로와 기업목록 기반 발견을 병행하고,
기존 후보/독립 검수에서 찾은 후보가 적절한 이유 없이 사라지지 않았는지 대조한다.
일반 방식·rc.2·엔진 방식은 같은 기간/원문 집합과 비교 가능한 자원을 사용한다. 이미 정답을 본
세션을 평가자로 재사용하지 않는다. 결과 수만 늘리는 것과 유효 기회를 더 잘 발견하는 것은 다르다.
'전국 재현율 100%'를 만들지 않는다. 실제 발견 여유·잘못된 제외·기존 상태 보존·사용자 교정량을 본다.

### E. 배포

원본 rc.2 회귀검사와 새 engine 검사, 기존 release builder·manifest를 함께 확인한다.
Windows/Python3.10/3.13 CI는 설정만 하지 말고 실제 원격 결과를 확인한다.
비공개 회복 파일·DB·원문·로그·키가 공개 commit/artifact에 없는지 검토한다.
개발 브랜치/Draft PR은 가능하나 정식 release/main merge/예약 교체는 미검증 상태에서 하지 않는다.

## 중대한 실패

레거시 후보 근거 없는 소실, 표본검색을 전국조사로 표현, 제목으로 필수/우대 판단,
불발견을 자동 종료, 전환형 인턴 수용을 출근일 제약 삭제로 확대, 간결함을 이유로 추천 삭제,
실제 네트워크/호스트 미실행을 pass로 표시하는 것은 출시를 막아야 할 결함이다.
