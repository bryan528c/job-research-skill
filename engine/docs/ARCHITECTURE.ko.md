# 구조: AI의 자율성과 조사 실행 보장을 분리한다

## 계층

**스킬/호스트 AI**는 관련 메모리 조회, 자연어 조건 해석, 검색어·산업·직무 확장, 적합성 판단,
불확실성 처리, 짧은 설명과 선택형 후속 준비를 맡는다. 고정 기업 수·검색 횟수·추천 개수는 없다.

**엔진**은 알려진 모집단과 실제 작업의 관계를 관리한다. SQLite+CLI로 시작해 별도 서버를
필수화하지 않는다. 출처 수집→원문 보존→후보 버전→AI 평가→보고의 각 단계에 ID가 남는다.

**출처 계층**은 기업별 공식 목록, 공개 채용 API, 기업명부, 실제 호스트 브라우징을 병행한다.
한 API나 상장기업 명단을 한국 전체 기업으로 부르지 않는다. 익숙한 기업만 관리 대상으로
삼지 않으며, 회사별 채용 URL이 없으면 `source_discovery` 작업이 생성된다.

## 데이터와 책임

- registry_snapshots/company_memberships: 원본 출처, 관찰 시각, 범위, 원본 해시, 행 수.
- companies: 출처 내 고유 ID. 그룹 소속·기업 규모·상장 여부는 서로 다른 속성.
- sources/run_sources: 실제 채용 출처와 사용 허용 경로; 이번 계획과 끝까지 확인한 상태.
- runs/run_companies: 선언된 계획. 실행 후 어려운 회사를 삭제해 완료율을 높일 수 없도록 대조.
- tasks/pages: 작업 임대, 만료 복구, 페이지 커서, 반복 페이지·총건수 불일치·변경 감지.
- observations: 실제 수집 또는 호스트 내보내기/fixture 구분, 원문·해시·도구 참조.
- jobs/job_versions/job_sightings: 역할·회차·출처 ID, 변경 이력과 이번 회차 관찰.
- profiles/assessments/user_events: 평가 버전, 사용자 결정·제출/전형을 모집 상태와 분리.
- assessment_reporting: schema2에 추가한 선택 metadata. 중요 확인, 원문 공백, 미래 Pool을 구분하며 추천은 숨김 tier를 허용하지 않는다. 보고 감사는 별도 보존 gap ID도 대조한다.
- legacy_records: 예전 대화의 후보를 근거 수준 그대로 회복. 미해결을 완료로 바꾸지 않음.
- audit_checks/reports: 다른 경로 검수, 발견 후 추가 조사, 추천-보고 일치와 번호 매핑.

## 작업 상태

`queued → leased → done`가 정상 흐름이다. 페이지가 남으면 커서를 저장하고 다시 queued.
접근 불가/인증 없음/파서 변경은 blocked. 429/일시 오류는 not_before 이후 재시도 가능.
임대가 만료된 작업은 새 토큰으로 회수한다. 이전 작업자는 이미 만료된 토큰으로 저장할 수 없다.
총건수 변화처럼 스냅샷을 다시 읽어야 하는 실패는 기존 작업을 superseded로 보존하고 새 scan을
만든다. 과거 원문·후보를 삭제하지 않는다. 이 엔진의 보장은 SQLite 트랜잭션과 임대 확인 범위다.

## 실제 완료는 한 종류가 아니다

원본 명부 적재, 출처 목록 소진, 개별 상세 확인, 개인 평가, 누락 검수, 보고 저장, 전달은 별개다.
`scope_checked`는 등록된 해당 계획의 기록 정합성이다. 전국 시장 완전성/실제 브라우징의 진위는
인증하지 않는다. `national_coverage`는 검증 근거 없이는 항상 unknown이다.

분모는 등록된 회사 ID 집합이다. 레지스트리 간 동일법인 통합이 미완료면 서로 다른 출처 ID가
동일 회사일 수 있다. 그 수를 한국의 고유 회사 수라고 발표하지 않는다.
현재 metric 이름은 `companies_registered_sources_checked`로, 모든 채용 채널 확인을 뜻하지 않는다.

## 중복과 변동

출처+external_id+round_key로 공고 이력을 보존한다. 같은 URL의 복수 직무는 `split-job`으로
원문 구절을 확인해 분리하고 parent/child 이력을 남긴다. 공식 법인/사업자/종목 식별자는
identity 모듈의 reversible alias로 연결한다. 충돌과 미확정 브랜드는 자동 합치지 않는다.
플랫폼 간 의미적 공고 병합은 독립 기회로 과대 집계하지 않도록 별도 검수가 남는다.

필수요건·본문이 바뀌면 content_hash가 바뀌어 기존 평가가 무효화된다. 사용자 조건이 바뀌면
profile_revision이 바뀐다. 예전 추천은 사라지지 않고 '재확인'으로 내려간다. 예전 제외도
오래된 사실에 기반했다면 pending으로 돌아가므로 false negative를 영구화하지 않는다.

목록에서 안 보이면 missing_job_recheck. 출처가 실패하면 해당 출처 공고를 일괄 마감하지 않는다.
날짜만 있는 마감에 23:59를 만들지 않는다. 표시 마감 경과와 원문이 여전히 open인 충돌은
연장 확인 대기로 보존하며 신규 지원 조언에서는 제외한다. 지원 결과를 불합격으로 바꾸지 않는다.

## 보안/권한

GET HTTP 및 명시적 allowlist의 공개 SK 검색/LG·한화 읽기 JSON POST, 승인된 출처 정책, 공개 IP 확인 후 IP 고정 연결, 리다이렉트별 재검사,
credential-bearing redirect 거부, 크기·시간 상한, 429 backoff, robots 확인을 구현했다.
캡차·로그인·약관 제한을 우회하지 않는다. robots 허용만으로 약관 동의를 대체하지 않는다.
실제 LLM 외부 호출·메모리 가져오기·원격 저장·지원서 제출은 이 모듈이 수행하지 않는다.
개인 DB는 로컬 사용자 권한에 의존하며 암호화/다중 사용자 서버 격리 보장은 없다.
