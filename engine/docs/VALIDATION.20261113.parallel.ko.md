운영 DB·설치 스킬·예약을 바꾸지 않은 검증 사본의 결과다. 기준은 `d9d3fc7`이며,
전국 조사 완료나 운영 전환을 승인하는 검증이 아니다. 원문·개인 판정·프로필·DB·경로·보고
매핑은 공개하지 않는다. 공개 저장소의 신규 테스트는 합성 자료만 사용한다.

## 실제로 고친 동작

- 접수 시작 전 `upcoming` 평가는 시작 시각 이후 현재 상태·지원 경로 재검수 대상으로 다시
  표시된다. 시간이 지났다는 이유로 모집 상태를 OPEN으로 바꾸지 않는다.
- 동일 법인·개별 직무·같은 회차라는 실제 근거가 있는 공고만 `link-postings`로 연결한다.
  그 연결을 따라 제출·거절 이력이 적용되고, 보고는 하나로 표시하면서 모든 출처 ID를
  매핑에 보존한다. 회사명·같은 제목·공채의 다른 직무만으로 연결하지 않는다. 연결 해제와
  원래 이벤트·과거 보고는 보존한다.
- 직무 분해에 필수/우대/업무/공통 조건의 원문 인용을 따로 저장할 수 있다. 인용은 공채와
  해당 직무 설명에 모두 있어야 하며 형제 직무의 요건을 자동 상속하지 않는다.
- GameJob의 공개 개별 공고와 실제 관측된 두 설명 iframe을 각각 저장한다. 정확한 공고
  ID·경로를 확인하고 이미지·차단·미확인 지원 URL은 남긴다. 카테고리 목록은 실제 개별
  공고 링크만 후속 큐에 넣어 메뉴/다른 필터가 앞을 차지하는 문제를 막는다. 페이지 완주는
  아직 별도 계약이 필요하며 부분 목록을 완료로 표시하지 않는다.
- 공개 플랫폼 헤더의 경력/마감과 구조화 데이터의 요약·날짜·주소를 구분한다. 직접 읽은
  URL을 보존하고, 미검증 SEO 날짜를 실제 마감으로 사용하지 않는다. 한국어/영어의 명시적
  접수 마감 버튼을 처리하며 403·불발견·미확인을 마감으로 바꾸지 않는다.
- `amend-deadline`은 원문 본문과 시각을 유지한 채 별도 헤더 근거로 마감을 보정한다. 이전
  판정은 stale이며 본문+새 마감 근거가 재평가에 필요하다. 늦게 도착한 옛 본문/헤더는 더
  최근의 마감 근거를 덮지 못한다. `init`도 실제 schema3을 표시한다.
- 감사는 모집 상태, 지원 상태, 평가 여부를 독립 집계한다. 종료와 제출을 하나의 상태로
  합치지 않으며 미평가를 제외로 세지 않는다.

## 독립 작성 12개 직무와의 소규모 대조

별도 담당자가 공식/직접 페이지에서 작성한 표본을 먼저 전달했다. 현재 평가자는 표본을
봤으므로 맹검이 아니다. 회사 수·공고 수·전국 재현율의 대리 지표로 사용하지 않는다.

첫 비교는 같은 저장 상태의 두 사본에서 기존 소스와 동일한 `collect`/`discover` 예산으로
실행했다. 두 실행의 네트워크 속도가 달라 처리량도 달랐으므로 속도 우열은 판단하지 않는다.
기존 표본 5개 보존과 새 발견을 나눴다. **이 단계의 신규 표본 발견은 양쪽 모두 0개다.**
그 후 제공된 URL 직접 수집과 실제 호스트 원문 판독·재평가를 별도 개입으로 수행했다.

| 지표: 표본 직무 단위, 중복 집계 가능 | 기준 엔진/기존 소스 | 수정 엔진/기존 소스 | 직접 URL·호스트 보완 후 |
|---|---:|---:|---:|
| 관련 출처 미등록 | 7 | 7 | 0 |
| 미발견 | 7 | 7 | 0 |
| 미평가·재평가 필요 | 0 | 1 | 3 |
| 확인된 오분류 | 1 | 1 | 0 |
| 보고 누락 | 2 | 1 | 0 |
| 중복 개별 직무 | 0 | 0 | 0 |
| 마감 오류 | 1 | 1 | 0 |
| 확인된 링크 오류 | 0 | 0 | 0 |
| 상세 또는 모집 상태 확인 불가 | 9 | 9 | 4 |

미평가 3개는 이미 닫힌 보존 항목이다. 본문 이미지·공식 ATS 접근·미판독 상세가 남은 4개를
통과로 만들지 않았다. 링크 오류 0은 모든 지원 경로를 최종 제출까지 검증했다는 뜻이 아니다.
직접 보완 후의 미발견 0을 자연 발견 개선으로 읽으면 안 된다. 각 공고의 날짜·시각·수집/
판정/보고·기존 제출 상태를 나눈 실제 대조표와 원본 매핑은 비공개로 보존했다.

추가로 새로 노출된 8채널을 후속 처리했다. 전문 채널의 원래 목록에서는 개별 링크 40개를
확인했고, 잘못 큐에 들어간 메뉴 27개는 증거·작업 나이를 보존해 별도 표시했다. 원래 공고
URL 큐를 이어 실제 출처 직무 레코드 4개를 수집했다. 이미지 검수와 남은 페이지는 미완료다.
이는 고정된 완료 목표가 아니라 실행 체크포인트이며 위의 고정 표본 비교에 합산하지 않았다.

## 실제 재시도·보존과 합성 검사

구 엔진의 미지원 차단을 저장한 실제 전문 채널 진단 DB를 새 프로세스로 열어 재시도했다.
새 수집기는 실제 HTTP 읽기로 1개 공고를 저장했고 다음 수집은 0개였다. 두 번째 새 Python
프로세스에서도 같은 run·작업·개인 상태의 해시가 같았다. 이미지 미판독은 계속 남았다.
네트워크 장애를 인위적으로 만들거나 합성403을 실제 사이트403으로 부르지 않았다.

기존 후보·프로필·레거시 원문/연결·과거 보고 매핑·원관측 바이트·원래 작업 나이를 사본에서
대조하고 새 프로세스 복원을 검사했다. 법인 충돌 27개와 과거 후보 미확정 28개는 이번에
해결하지 않았으며 그대로 남는다. 빈/귀속 미상 충돌 행은 논리 법인 충돌과 다른 수치다.

최종 로컬 엔진 284개 통과, root 100개 중 96개 통과/4개 not_run(Windows symlink 권한).
실제 CI는 최종 커밋의 Actions 결과로 별도 확인한다. 합성 1만 명부 레코드·250공고의 재개와
의도적 오류4종 탐지는 실자료 양이나 실제 AI 판단 정확도가 아니다. 빌드·네이티브 ZIP
격리 실행·동일 해시 재빌드·실제 Git index/ZIP 개인정보 검사는 별개 검사다.

## Docling 분리 실험

[공식 v2.150.0](https://github.com/docling-project/docling/releases/tag/v2.150.0)과
[공식 설치 문서](https://docling-project.github.io/docling/getting_started/installation/)를 확인한 뒤,
임시 Python 환경에 공식 PyPI 휠만 설치했다. 설치 보고의112개 다운로드 호스트는 모두
`files.pythonhosted.org`다. 기존 추출기·스킬·예약에는 연결하지 않았다.

공식 공고 이미지2건으로 한정했다. 하나는 공식 파일 획득이 native robots와 실제 브라우저
차단에 막혀 OCR not_run이다. 읽을 수 있는 공식 헤더 마감과 미판독 자격 이미지를 구분했고
미러 이미지를 공식 입력으로 대신 사용하지 않았다. 다른 하나는 실제 브라우저에 로드된
공식 JPG를 지원되는 자산 내보내기로 얻어 한국어/영어 로컬 OCR을 CPU에서 실행했다.

선택된 개별 직무의 이미지 내4필드를 사후 수작업 대조했다. 사전등록 성능 시험이나 맹검이 아니다.

| 경로 | 일치 | 오류 | 미확인/누락 | 실행 부담 |
|---|---:|---:|---:|---|
| 기존 공식 HTML 추출기+원본 이미지 참조 | 1 | 0 | 3 | 추출 약0.06초; 이미지는 판독 대기, 마감은 HTML 메타데이터에서 확인 |
| Docling2.150.0 원본 JPG | 2 | 1 | 1 | cold CPU 변환 약127초, 모델 취득 약27초 |
| 사람의 공식 원본 대조 | 4 | 0 | 0 | 직접 원본 판독; 소요시간 별도 계측 없음 |

Docling은 전공·Office 요건을 같은 직무 행에서 읽었지만 직무명 오독과 이미지 상단 마감
누락이 있었다. 필드 누락도 실패로 세면4개 중2개 실패다. 다른 행에서는 필수 언어 문구와
직무 일부도 빠졌다. 날짜만 있는 이미지에 시각을 추측해 넣지 않았다. 설치는 약10분,
가상환경 파일 약1.46GB와 모델/캐시 약0.82GB였다. 이는 이 PC의 대략적인 논리 파일 크기다.
원격 서비스·외부 플러그인을 끄고 개인 입력·외부 업로드 없이 실행했다.

[미해결 #4083](https://github.com/docling-project/docling/issues/4083)은 불완전한 PDF native-text
layer와 표 셀 정렬에 관한 이슈다. 이번 JPG 실험이 같은 조건을 재현하거나 해결을 입증한 것은
아니다. 변환 SUCCESS를 필드 정확도 PASS로 간주하지 않으며 **현재 파이프라인 전환은 보류**한다.

## 다음 비교 회차와 롤백

실제 예약 호스트 실행·상태 지속·원래 채팅 전달은 not_run이다. 로컬 복원으로 대체하지 않는다.
독립 검수자는 다음 회차의 공식 표본과 관측 시각을 먼저 고정하고, 작업자는 표본을 시드/
질의/채널에 넣지 않은 상태의 기존 범위를 먼저 저장한다. 이후 직접 수집 시험을 따로 한다.
2·3회차는 변경·연장·지난 회차·이미 제출한 항목과 미탐색 전문 채널의 잔여 분기를 포함한다.
판정이 충돌하는 사례는 원문과 개인 근거를 분리해 다른 검토자가 재판정할 수 있게 보존한다.

실행 호스트는 Python3.10+, 승인된 비공개 DB와 프로필, 공개 검색/브라우저 접근이 필요하다.
Docling 환경은 엔진 실행에 필요하지 않다. 호스트가 locator를 읽고 아래 변수를 채운다.

```powershell
python skills/job-research/scripts/research.py --db "$env:JOB_RESEARCH_DB" session "$env:JOB_RESEARCH_PROFILE" "나한테 맞는 공고 찾아줘"
python skills/job-research/scripts/research.py --db "$env:JOB_RESEARCH_DB" packet "$env:JOB_RESEARCH_RUN" --section tasks --page-size 50
python skills/job-research/scripts/research.py --db "$env:JOB_RESEARCH_DB" collect "$env:JOB_RESEARCH_RUN" --details --allow-network --budget-seconds 30
python engine/tools/compare_runs.py "$env:JOB_RESEARCH_COHORT" "$env:JOB_RESEARCH_RUN_EXPORT" --output "$env:JOB_RESEARCH_COMPARISON"
```

page/budget는 재개 경계이며 완료 조건이 아니다. 커서를 계속 읽고 노출된 중요 분기를 처리한다.
전체 입력/결과를 Git 밖에 보존하고 비교 `mode`, `sample_seeded`, `blind=false`, 원관측 시각을
기록한다. 표본 URL 직접 입력 결과와 복원된 기존 후보를 신규 자연 발견으로 세지 않는다.

롤백은 별도 작업 사본에서 기준 `d9d3fc7`을 실행해 같은 비공개 스냅샷과 대조하거나 이번
개발 커밋을 되돌리는 방식이다. 기존 사용자 체크아웃을 reset하지 않는다. 운영 상태를 이
검증 사본으로 덮지 않았으므로 설치 스킬·예약·운영 DB를 되돌릴 작업은 없다.
