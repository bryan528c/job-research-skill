# Host adaptation — capability, not brand assumptions

Canonical behavior is in SKILL.md. Provider-specific tool names and native memory APIs
are deliberately absent. Do not force install scripts, Python, a database or MCP just
to start. Registration/import is not evidence of runtime execution.

Use the best actually available route:
1. Native skill support: load this whole folder and resolve reference files locally.
2. Supported custom instructions or file context: use the self-contained portable guide;
   do not claim it is installed, automatically selected or permanently remembered.
3. No web: review supplied material; current openness and broad discovery are unverified.
4. No memory: use this conversation, then ask only consequential career questions.
5. No scripts: carry out the same evidence checks conversationally.
6. No private persistence: keep current working notes and disclose material continuity gaps.
7. No scheduler: perform only current work; never promise autonomous future delivery.

Check only what matters, with harmless reads when possible. Record capability as
available/limited/unavailable/unknown, evidence and time; no visible configuration
survey. Never infer memory access from login, provider name or a local skill directory.
The UI app, CLI, project, API and scheduled/cloud session may expose different tools.
Use the user's current language and locale; preserve source timezone when user timezone
is unknown rather than guessing it.

A plugin/skill is not a shared-memory bridge, public-web permission or credentials.
If moving to another model, user-controlled minimal handoff is optional. No automatic
cross-provider memory export. Do not downgrade a rich host to the lowest-common-denominator:
use its authorized browsing, files, multimodal reading and delegation when beneficial.

At first runtime validation, verify actual skill version loaded, access to one reference,
one harmless live-source read if supported, relevant-memory visibility if available,
clickable result rendering and selected-job continuation. Save and scheduling are
separate tests and need permission. Mark each host actually exercised or not_run.
